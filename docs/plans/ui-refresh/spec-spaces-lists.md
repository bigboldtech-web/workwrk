One sentence for the founder: a Space is a team's room, a Folder is a shelf in it, a List is a set of tasks with as many ways to look at it as you like, and every one of them shares, moves, archives and deletes the same way from the same "…" menu.

**No route here carries `?item=`.** Cross-unit resolution: the task-detail unit owns how a list opens a task, and the mechanism is a Next intercepting route, not a query parameter. A row or card click calls `router.push('/item/<id>')`; the host route mounts the `@drawer` slot, so Next renders the intercepted drawer over the list and the URL becomes `/item/<id>`. Closing returns to the host URL with the saved view and scroll position intact; Expand keeps the same URL and swaps the drawer for the full page. `?item=<id>` survives one release as a 308 to `/item/<id>` on every route in this unit. One URL per task means Copy link always works, which is the point. The one prop name across page, drawer and panel is `host`, and this unit never passes it: the List chassis renders the host, the task-detail unit renders the slot.

Not a route but owned here: the Spaces tree in the Work sidebar (`src/components/layout/os/space-tree-row.tsx`, `space-more-menu.tsx`, `folder-more-menu.tsx`, `board-more-menu.tsx`, `space-create-popover.tsx`), the create dialogs (`new-space-dialog.tsx`, `new-folder-dialog.tsx`, `create-list-modal.tsx`, `create-sprint-modal.tsx`), the List page chassis (`src/components/board-view/*` except `board-item-detail.tsx`, `board-item-drawer.tsx`, `item-thread.tsx`, `date-planner.tsx`, which the work-tasks unit owns as the task detail), the Template Center (`src/components/templates/template-center.tsx`), and the one share dialog's three container flavours (Space, Folder, List), which is the access model's `src/components/access/share-dialog.tsx` rendered with a container object.

## 1. Unit-level rules

### Hub + sidebar

Every route here is in the **Work** hub; the rail highlights Work from the URL (`/spaces`, `/folders`, `/boards`, `/templates`, `/trash` all match Work). The secondary sidebar is the Work hub sidebar (owner: work-tasks unit); the active row is derived from the URL on every render, never from stored state:

| URL | Active sidebar row |
|---|---|
| `/spaces` | the SPACES section label (rendered as active text, no pill) |
| `/spaces/[slug]` | that Space's row; its subtree expanded |
| `/folders/[id]` | that Folder's row; ancestors expanded |
| `/boards/[slug]` | that List's row; ancestors expanded; if the active saved view is a child row (see Tree › view rows), that view row |
| `/templates` | none in the tree; the row "Templates" in the Work sidebar's personal group is active |
| `/trash` | the row "Trash" in the Work sidebar's personal group is active |

Work hub sidebar order (design system §4.2): personal rows (Home, My work, Inbox), then FAVORITES (only when non-empty), then SPACES. This unit adds two rows to the personal group's tail, both 36px, `--os-ink-2` icon, no count: **Templates** (`LayoutTemplate`, `/templates`, every Member; never Guests) and **Trash** (`Trash2`, `/trash`, every Member; never Guests). They sit under a 1px `--os-line` rule after Inbox so the personal group reads Home · My work · Inbox · Templates · Trash. The work-tasks unit owns the group and must render these two rows (§4). The shell's `ROUTE_HUB` keeps both `/templates` and `/trash` under **Work**, unchanged: docs-knowledge's request to move the `/templates` prefix to Docs is declined (§0), and no hub but Work carries a Templates or Trash row. Other hubs reach them by link only, scoped with `?kind=` and `?type=`.

### Keyboard

The shell owns `src/lib/shortcuts.ts`, the single source for the window listener, every tooltip hint, the `?` overlay and `/account/shortcuts`. This unit registers no chord of its own and prints only what the shell registers. The quick-task chord is **`⌘⇧K`**, not `⌘T`, and the hub jumps are **G then 1 to 8**, not `⌘1` to `⌘8`: `⌘T` opens a new tab and `⌘` plus a digit switches tabs in Chrome, Safari, Firefox and Edge on both platforms, so printing them would break the rule that an advertised shortcut must work. Every `⌘⇧K` hint in §2 is a tooltip on the "Create task" primary; the button label stays "Create task". Row-local keys (↑ ↓, Space, Enter, Esc, ← →, type-ahead in pickers) are element-scoped, never global, and need no registration.
