**Denial: three situations, three screens, and which one applies where.** The audit found six units reaching three different answers; they are all correct, for different cases, so the three are written out once here and every Denied line in §2 points at one of them by name:

1. **An app key the viewer's rule excludes** (`planner`, `timesheets`, and the proposed `meetings` and `clock` for a Guest, or for anyone in an org whose Apps config hides them): the **in-shell 404**, with no sidebar row to click in the first place. Access §5.5 rule 6: there is no object, so there is nobody to request access from. No `LockedPage`, no Request access. teams-people's two app-key `LockedPage`s on `/team` and `/team/workload` are the single sanctioned exception in the audit, kept because that unit supplies those `APP_RULES` rows itself; they are not a precedent for the `meetings` and `clock` rows proposed above, which take the in-shell 404 like every other key.
2. **A view of a page the viewer already holds** (`/planner?calendar=team`, `/timesheets?view=approvals`, `/timesheets?view=team`): the page's own default view, the parameter stripped, one notice line. Access §5.5 rule 4, "has a role but not this action". The four-step behaviour below is that rule's implementation and is identical on every route here.
3. **An object the viewer can discover but holds no role on**: `LockedPage` with name, owner avatar, `decision.reason` and Request access (access §5.3, rule 3). **No surface in this unit reaches this case**, because the only object-scoped route here is `/meetings/[id]` and a meeting a viewer does not attend is not discoverable at all (rule 14, 404). So `LockedPage` never renders in this unit, which is a fact about meetings rather than a rejection of the shape.

`AppOff` is reserved for an app the org hid or floored in Apps config, and `ModuleOff` for a premium module switched off; neither is a substitute for the three above.

**Situation 2 in full** (`/planner?calendar=team`, `/timesheets?view=approvals`, `/timesheets?view=team`). These are views of a page the viewer already holds, not objects, so there is no owner to request access from and `LockedPage` does not apply. One behaviour, identical on both routes:

1. The view pill is not rendered (access §5.4: a control the role cannot use is not rendered, never disabled).
2. A typed or stale URL renders the route's own default view (My calendar, My timesheets) and `router.replace` strips the parameter, so the URL and the screen agree.
3. One 13/400 `--os-ink-2` notice line sits under the toolbar for that page load only: "Team calendar shows the people who report to you." / "Approvals show the people who report to you." No icon, no button, no Back link.
4. The API returns 403 with the reason; the client shows the one 403 toast (access §5.5 item 4) without a Request access action, because there is no object.

No new `LockedPage` variant is introduced anywhere in this unit, and no route here substitutes one screen for another: an excluded app key 404s, a view the role cannot use falls back with a notice line, and nothing in this unit is a discoverable object without a role.

Non-human principals: the calendar-sync cron acts as the subscription owner (`viewerForCron(orgId, userId, EDIT)`) and writes only that person's events; the reminders cron acts as each reminder's owner. `ActivityLog.actorType: "cron"` on every write.

### Keyboard rule for the whole unit

Every chord (`⌘`-based) works everywhere. **Single-letter shortcuts never fire while focus is inside a text input, a textarea, a contenteditable notes editor, a picker's search field, the timesheet add row or any open modal**; in those places only chords and Esc work, and Esc returns focus to the surface behind before a single letter is live again. Design-system §4.7 defines chords only, so this suppression rule is written here and flagged to the shell unit for the shared shortcut map (`src/lib/shortcuts.ts`), which is where it belongs once that map exists. Every route's Keyboard block below is read under this rule.

## 2. Route specs

### `/planner`  (`src/app/(dashboard)/planner/page.tsx`)

- **Purpose**: see everything with a time on it (my tasks, meetings, events from Google, reminders) in one calendar, and for managers, the same for their people.
