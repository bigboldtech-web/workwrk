# Talk spec

Unit: Talk (chats, channels, threads, DMs, calls, the call dock, the guest call door, announcements). Written 2026-09-11 against `main` at `6187227a`, the audit inventory `comms.md`, and the three decided documents (`design-system.md` for look, `access-model-spec.md` for access, `settings-architecture.md` for settings). Everything below is in the user's words; system internals appear only in the Data rows. No em dashes, no double hyphens in prose; tokens such as `--os-brand` are code.

The one sentence: **Talk is where your company talks: channels for teams, direct messages for people, a call one click away, and announcements everyone must see.**

## 1. Unit-level rules

### Hub + sidebar

| Route | Rail hub active | Sidebar row active |
|---|---|---|
| `/tlk` | Talk | Unread |
| `/tlk?view=threads` | Talk | Threads |
| `/tlk?view=mentions` | Talk | Mentions |
| `/tlk?c=…`, `/tlk?view=…&c=…` (something open in the detail pane) | Talk | the `?view` row stays active (Unread, Threads or Mentions). The conversation's own row in CHANNELS or DIRECT MESSAGES is **not** active: the URL is still `/tlk`, one row is active or none, and the pane is a preview of the list you are standing in. Opening the same conversation as a page (`/tlk/[id]`) is what moves the highlight |
| `/tlk/[id]` | Talk | the conversation's row (in STARRED if starred, else CHANNELS or DIRECT MESSAGES) |
| `/announcements`, `/announcements/[id]` | Talk, always (module on or off) | Announcements |
| `/tlk/*` when the Talk module is off | Talk (the hub renders; `/tlk` shows `ModuleOff`, §2.0) | none |
| `/meet/[code]` | no shell (public) | none |

Highlight and sidebar are derived from the URL on every render by the shell's `resolveHub(pathname)` over `ROUTE_HUB` and `resolveActiveRow(rows, pathname, search)` (`spec-shell.md` §1.1), never the stored `activeAppKey`. `AppEntry.matchPaths` and `findAppForPath` are deleted by the shell unit and are not used here. `ROUTE_HUB` already maps both `/tlk` and `/announcements` to the `chat` (Talk) hub, and it stays that way: it is a pure static table, so it cannot and must not branch on whether a module is installed.

**Announcements never leaves the Talk hub.** Announcements is not module-gated (anyone who works here reads them), so the Talk hub has to stay reachable when the Talk module is off:

- The Talk rail hub renders when the Talk module is on **or** when the viewer can see the folded `announcements` app (`can(viewer, "view", { type: "app", key: "announcements" })`). Flagged to the shell unit: `visibleRailApps` must keep the `chat` hub on that second condition, which is the one line this rule costs.
- With the module off, the Talk hub's `defaultHref` is `/announcements` instead of `/tlk` (flagged to the shell unit, which owns the `defaultHref` table), and the Talk sidebar renders **only** the Announcements row: no Unread, Threads, Mentions, STARRED, CHANNELS, DIRECT MESSAGES, no header "+" entries for messages or channels. Cross-unit resolution with `spec-shell.md` §1.1: the conditional stands, and **Talk is the only conditional `defaultHref` in that table**; every other hub opens one fixed URL, and `naming-canon.md` §1 records the pair as "`/tlk`, or `/announcements` when the Talk module is off". The rail label stays **Talk** in both states.
- The branch lives in the shell's `defaultHref` resolver and in `visibleRailApps`, never in `ROUTE_HUB`: `ROUTE_HUB` stays a pure static table mapping `/tlk` and `/announcements` to the `chat` hub, and it never reads module state. Which hub opens where and which hubs render are runtime questions; which hub owns a URL is not.
- `/tlk` and `/tlk/[id]` still render `ModuleOff` in that state (§2.0), so the module switch is exactly where an Owner or Admin looks for it.
- With the module off for the whole org and the `announcements` app hidden by an Admin, the Talk hub does not render at all and both routes answer per §1 Access.

`G` then `4` jumps to the Talk hub (rail order Work, Planner, AI, Talk, Teams, Docs, Tables, Settings). The shell replaced `⌘1..8` with `G 1..8` because ⌘digit is a browser tab switch (`spec-shell.md` §1.8); no `⌘4` is advertised anywhere in this unit.

### Access

Talk is a premium module (`ProductInstallation` `workwrk-talk`). Every object here is a `{ type: "channel", id }` ref (DMs and groups included); `can()` rule 2 (module off) fires before anything else. Object roles are the access spec's, no Talk-specific vocabulary:

| Conversation kind | Who reaches it | Role | Owner | Admin read-around |
|---|---|---|---|---|
| Public channel | every Member (EVERYONE EDIT, findable, self-join creates the `ConversationMember` row) | Can edit for members; the creator holds Full access | `Conversation.createdById` (pinned Owner in the share dialog; transferable) | Owners and Admins hold Full access (rule 4) |
| Private channel (`restricted = true`) | people added to it | Can edit; creator Full access | same | **none** (rule 3): Owners and Admins see its name and member count in Browse channels › All channels and may Archive it (`org.archive_channel`, audited), never read it |
| Group | people in it | Can edit; creator Full access | same | none (rule 3) |
| Direct message | the two people | Can edit for both; nobody holds Full (no rename, no members) | none | none (rule 3) |
| Space-linked channel (`Conversation.spaceId`, reserved) | inherits the Space (Edit+ posts; View/Comment reads) | inherited | the Space owner | as the Space |
| Archived conversation | as above, capped at Can view; Full holders may Restore | | | |

What each role renders (the read-only rule from access §5.4, applied to Talk):

| Role | Renders | Does not render |
|---|---|---|
| Can view (archived channel, Space-linked channel at View or Comment) | messages, threads, files, Details panel, Copy link, one slim banner "Archived. Ask {owner} to restore." or "View only." | the message box, reactions, Add people, Call, Share |
| Can comment (Space-linked at Comment) | as View plus reactions and thread replies | posting new top-level messages, Add people, Call |
| Can edit (a member) | post, edit and delete own messages, react, threads, attach, Start a call, Copy guest link, Add people (public channels always; private channels and groups only when access toggle 4 "Editors can share" is on), Star, Notifications, Leave | Rename, Topic, Remove members, Restricted, Findable, Archive, Reset guest link, Transfer |
| Full access (creator, Owner and Admin on public channels) | everything | nothing hidden |

Guests: Talk hub only when they hold at least one channel; sidebar shows exactly those rows; New message's picker lists only people who share an object with them (`accessibleUsers`); Browse channels and Announcements never render; `/announcements` is a 404 for a Guest. Agents: exactly a Member. Every mutation goes through `requireCan(action, { type: "channel", id })`; `getSessionAndModule` in the 19 Talk API files becomes the rule-2 short-circuit inside `can()` (access step 1 wrapper, step 6 cleanup).

Denial, one convention (access §5.5): not signed in → `/login?callbackUrl=`; module off → `<ModuleOff module="Talk">` from the `/tlk` layout (Owners and Admins get the switch, Members "Ask an admin" with Owner and Admin avatars, Guests 404; §2.0); the `chat` or `announcements` app hidden or floored by an Admin in Workspace settings › Apps & modules › Rail apps → `<AppOff>` at the same URL, with a link to `/settings/apps` for Admins, which is why the sidebar row, the page and the palette entry all read the same rule (§1 Hub sidebar contents row 4); a conversation I am not in → 404 inside the shell, except a findable public channel, which renders `LockedPage` with the channel name, owner avatar and one primary **Join channel** (self-join replaces Request access for public channels); a private channel or DM I am not in → 404 (never confirmed); an action my role lacks → not rendered, and a stale tab's API call returns 403 with one toast "You need Full access for that. Ask {owner}."

### One primary per page (the yielding rule)

Design principle 0.1 is "one blue thing per page". Two surfaces in this unit can put a second blue button on screen, so the rule is stated once here instead of being asserted per surface, and is flagged to the design system as a clarification to §5.10:

1. **A drawer or modal over a list owns the primary.** While `/announcements/[id]` is open as a drawer over `/announcements`, the list's toolbar **New announcement** renders as a secondary button (border, `--os-ink`) for as long as the drawer is open, and returns to blue on close (120ms background transition, no movement). The drawer's **Acknowledge** is then the one blue thing on screen. The same applies to every modal in this unit: the composer's **Post**, New channel's **Create channel**, Add people's **Add N** are the one primary while open. This is the general rule, not an announcements special case.
2. **Shell overlays are exempt from the page count.** The call dock, the incoming call card and toasts belong to the shell, not the page; they float over every route including the Settings takeover, and no page can know about them. The incoming call card's **Join** is therefore blue while the page underneath keeps its own primary. There is at most one shell overlay primary at a time (one card per conversation, the dock has no primary), so the screen never shows more than two blue buttons and never two on the same plane.

### Dates and times (critic #13)

This unit renders day dividers, message times, "(edited)", call elapsed time, "Created by Anita Rao · 4 Sep", "Posted 5 Sep 10:12", "Expires 30 Nov", "Scheduled for 12 Sep 09:00", "Reminded 3h ago", "Expires in 23h" and two date pickers. All of them obey one rule:

- Every instant is stored UTC and rendered through the one `formatDate` helper reading the viewer's `home.locale.{timezone, dateFormat, timeFormat, weekStart}` (settings §4.2). No surface in this unit formats a date itself, and none assumes the server's zone.
- Day dividers, "This week" and "Earlier" grouping and the "unread since" line bucket by the viewer's local day, not UTC.
- The composer's **Post › Schedule** and **Expires** pickers read and write in the viewer's time zone; the field shows the zone abbreviation beside the time whenever the viewer's zone differs from the organization's (`settings.locale.timezone`), so an announcement scheduled from Mumbai for a London office states which 09:00 it means. The stored value is a UTC instant; the publish cron and the expiry filter compare instants, never local strings.
- Announcement cards and the detail page show relative time under 24 hours ("2h ago") and an absolute date after, both from the same helper. Week start affects only the date picker's month grid.
- Call elapsed time and "Expires in 23h" are durations, not clock times: they are computed from the difference of two instants and are identical in every zone, rendered in JetBrains Mono with `tnum`.
